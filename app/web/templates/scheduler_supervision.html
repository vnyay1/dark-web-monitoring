Cette interface frontend consomme les 5 routes suivantes pour piloter le scheduler et streamer les logs :

GET /scheduler/api/status
Retourne le statut actuel : { "actif": true, "statut": "actif"|"inactif"|"en_cours", "intervalle_heures": 6, "prochaine_execution": "..." }
POST /scheduler/api/demarrer
Démarre le service scheduler en tâche de fond. Retourne : { "succes": true, "message": "Scheduler démarré" }
POST /scheduler/api/arreter
Arrête le service scheduler. Retourne : { "succes": true, "message": "Scheduler arrêté" }
POST /scheduler/api/executer-maintenant
Lance immédiatement une passe des 7 connecteurs sans attendre l'intervalle. Retourne : { "succes": true }
GET /scheduler/api/logs/stream (Content-Type: text/event-stream)
Flux Server-Sent Events émettant des payloads JSON : data: {"timestamp": "...", "level": "INFO", "message": "..."}
